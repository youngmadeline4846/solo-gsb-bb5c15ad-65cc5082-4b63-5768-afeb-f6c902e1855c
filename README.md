# 论证稳定性沙盘（Argument Stability Sandbox）

一个用于构建和检验论证网络的 Web 应用。用户可以创建**观点**与**证据**节点，拖拽连线标记为**支持**或**反驳**并设置权重；系统会从节点初始可信度出发，在允许有向环的图上进行同步迭代传播。收敛后显示最终可信度；若检测到持续振荡，则停止计算并高亮导致振荡的负反馈环。每次计算后还可用**传播回放**逐轮回看：画布按当轮可信度着色、显示相邻轮升降，选中节点可核对下一轮值的完整分解。

## 唯一启动命令

确保已安装 Docker Engine 与 Docker Compose Plugin，然后在项目根目录执行：

```bash
docker compose up --build
```

启动成功后访问：

- 地址：<http://localhost:8080>
- 端口：容器内固定 `8080`，宿主机默认映射 `8080:8080`

后台运行可使用：

```bash
docker compose up --build -d
```

停止并保留 SQLite 数据：

```bash
docker compose down
```

## 必要配置

通常无需任何配置。只有想改变宿主机访问端口时，复制 `.env.example` 为 `.env` 并修改：

```env
APP_PORT=8080
```

例如改为 `APP_PORT=3000` 后访问 <http://localhost:3000>。

其他运行时环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `8080` | 容器内 HTTP 端口，一般不需要修改 |
| `DATABASE_PATH` | `/app/data/argument.db` | SQLite 数据库文件路径 |

数据保存在 Docker named volume `argument-sqlite-data` 中。应用首次启动会自动创建数据库、表结构以及一张空白图；镜像构建阶段已经安装全部前后端依赖并完成构建。

## 使用指南

1. 点击顶部 **＋ 观点** 或 **＋ 证据** 创建节点。
2. 从节点右侧连接点拖到另一个节点左侧连接点创建连线。
3. 点击节点，可编辑名称、类型、初始可信度（0–100%）以及是否固定。
4. 点击连线，可在“支持 / 反驳”之间切换并调整权重。
5. 点击 **运行稳定性分析**：
   - 绿色状态表示达到收敛阈值；
   - 红色状态表示持续振荡或达到上限仍明显不稳定；
   - 节点显示最终可信度及相对变化；
   - 振荡时红色脉冲节点与加粗红色边标出负反馈环。
6. 计算完成后，画布左下角出现**传播回放**控制条（详见下节）。
7. 使用 **导出 JSON** 保存当前图，使用 **导入 JSON** 恢复。
8. 可先载入“稳定示例”或“振荡示例”观察两种结果。

## 边权敏感性扫描

想知道“这条边再强一点/弱一点，结论会不会翻盘”时：

1. 在画布上**点击选中一条连线**；
2. 右侧检查器下方出现「边权敏感性扫描」卡片，在“目标节点”下拉中选择要观察的节点（默认为该连线指向的节点）；
3. 点击 **扫描边权 0–1（21 点）**。

服务端会在**不保存图**的前提下，把该边权从 0 到 1 等距取 21 个值（0, 0.05, …, 1），分别沿用当前侧栏中的传播参数（收敛阈值、最大迭代、λ）各跑一次完整传播，前端以曲线展示目标节点的最终可信度：

- **收敛点**：绿色圆点，相邻的收敛点连成曲线；
- **振荡点**：红色菱形，**达到上限点**：橙色方块；这两类点没有稳定最终值，统一标在曲线下方的独立行中；
- **0.5 阈值线**以橙色虚线标出；连续收敛点序列中结果**首次跨过 0.5** 的采样区间会高亮为橙色“阈值带”，并在图上方给出区间与跨越方向（振荡或未收敛的点不参与跨越判断，也会打断连续性）；
- 蓝色虚线表示当前画布上该边的真实权重（扫描本身不会改动它）。

**悬停任意采样点**会显示：边权、状态（收敛 / 振荡 / 达到上限）、停止轮次、目标值；若该点没有目标值，则改为显示原因（例如检测到周期约为 N 的持续振荡，或达到迭代上限仍未收敛）。

扫描请求会把当前画布随请求一起发送，服务端只在内存副本上计算，**不写入 SQLite**；因此扫描期间画布上未保存的编辑也会被纳入计算，且扫描结束后图保持原样。任何图编辑（增删节点/连线、改权重、改先验等）都会使上次扫描结果失效，需要重新扫描；切换选中的连线会把目标节点重置为新连线指向的节点。扫描与编辑、传播回放互不影响。


## 传播回放

每次计算完成后，画布左下角的回放条可回看**第 0 轮（先验）到停止轮**的完整过程：

- **迭代滑杆**：拖动即可跳到任意轮次。画布按该轮可信度为节点着色（红 → 黄 → 绿），节点内的数值、色条同步更新，并显示相对上一轮的升降（▲/▼ 或“持平”）。
- **播放 / 暂停**：点击 **▶ 播放** 从当前轮逐轮前进（约每 0.8 秒一轮）。收敛结果播到停止轮自动停下，再按一次从第 0 轮重播；振荡结果则按检测到的周期在最后一个周期内**循环播放**（控制条上显示“周期 N 循环”徽标）。
- **下一轮值分解**：计算后点击任意节点，侧栏会展示「当前轮 → 下一轮」的可核对分解：
  - 先验 p 与本次计算实际使用的 λ；
  - 每条入边的有符号贡献（支持为正、反驳为负，即 ±权重 × 源节点当轮值）及其合计；
  - 裁剪前的值 `p + λ·Σ`；
  - 0..1 裁剪量（超出上界裁去多少 / 低于下界抬升多少 / 未裁剪）；
  - 底部核对行：前端用同一公式独立重算，与服务器记录的下一轮值逐位比对，显示“✓ 一致”。
  - 若当前已停在最后一轮，则展示最后一次迭代的分解。
- **固定节点**：分解卡片会明确显示其值由先验锁定（🔒），入边不参与计算，因此**不列出任何入边贡献**，不伪造数据。
- **无副作用**：拖动滑杆、播放、暂停都只是前端视图切换——不会修改图、不会触发重新计算或自动保存；回放状态不写入 SQLite，刷新页面后自然消失（图本身仍会持久化）。
- 任何图编辑（增删节点/连线、改权重等）都会使本次计算结果与回放失效，需重新运行分析。

## 传播模型

设节点 $i$ 的先验可信度为 $p_i$，当前可信度为 $b_i$，则每轮同步更新：

\[
b_i^{(t+1)} =
\operatorname{clip}_{[0,1]}\left(
p_i + \lambda\left(
\sum_{e:j\to i,\ support} w_e b_j^{(t)}
-
\sum_{e:j\to i,\ rebut} w_e b_j^{(t)}
\right)\right)
\]

- `λ`：传播强度，默认 `0.8`；
- 支持边提高目标可信度，反驳边降低目标可信度；
- 被标记为“固定”的节点始终保持初始可信度；
- 当最大节点变化小于收敛阈值时判定收敛；
- 系统比较最近若干轮的状态向量，发现稳定周期即判定振荡；
- 振荡检测后枚举有向简单环，优先报告具有奇数条反驳边、负增益较强且近期仍在移动的环。

这是一个带先验锚定的线性加权意见传播模型。强负反馈环（例如全强度的三角相互反驳）会产生持续周期；先验与默认传播强度通常会让常规论证图稳定。

## JSON 格式

导出的文件结构如下：

```json
{
  "version": 1,
  "name": "我的论证图",
  "nodes": [
    {
      "id": "e1",
      "label": "实验证据",
      "kind": "evidence",
      "initialBelief": 0.8,
      "anchored": false,
      "position": { "x": 100, "y": 80 }
    }
  ],
  "edges": [
    {
      "id": "edge-1",
      "source": "e1",
      "target": "c1",
      "stance": "support",
      "weight": 0.7
    }
  ]
}
```

约束：

- `kind` 只能是 `claim` 或 `evidence`；
- `stance` 只能是 `support` 或 `rebut`；
- `initialBelief` 与 `weight` 必须在 `0..1`；
- 节点 id 必须唯一，连线两端必须引用已存在节点；
- 导入时后端会进行严格校验并返回明确错误。

## HTTP API

- `GET /api/health`：健康检查；
- `GET /api/graph`：读取当前图；
- `PUT /api/graph`：整体替换并持久化当前图；
- `POST /api/propagate`：在当前持久化图上运行传播。响应中的 `result.traces` 记录每个节点第 0 轮到停止轮的逐轮可信度（传播回放的数据来源），`result.options` 为本次实际使用的传播参数。
- `POST /api/sensitivity`：边权敏感性扫描。请求体：

  ```json
  {
    "edgeId": "edge-e1-c1",
    "targetNodeId": "c1",
    "options": { "threshold": 0.001, "maxIterations": 200, "lambda": 0.8 },
    "graph": { "version": 1, "nodes": [], "edges": [] }
  }
  ```

  - `edgeId` / `targetNodeId` 必填，且必须引用图中存在的连线与节点，否则返回 `400`；
  - `options` 省略时使用服务端默认参数，21 个采样点统一沿用本次参数；
  - `graph` 可选：提供时扫描在该图的**内存副本**上进行（先经与 `PUT /api/graph` 相同的严格校验），**不会持久化**；省略时使用当前已保存的图。

  响应 `sensitivity` 的关键字段：

  | 字段 | 说明 |
  | --- | --- |
  | `points` | 长度 21 的数组，按 `weight`（0, 0.05, …, 1）升序；每点含 `weight`、`status`（`converged` / `oscillating` / `limit`）、`iterations`（停止轮次）、`targetValue`（仅收敛时非 null）、`reason`（无目标值时的原因）、`detectedPeriod` |
  | `thresholdBand` | 连续收敛点首次跨过 0.5 的区间（`fromWeight` / `toWeight` / `fromValue` / `toValue` / `direction`）；不存在时为 `null` |
  | `edge` | 扫描连线的快照（其 `weight` 为扫描前的真实权重） |
  | `options` | 本次实际使用的传播参数 |

示例：

```bash
curl -X POST http://localhost:8080/api/propagate \
  -H 'Content-Type: application/json' \
  -d '{"options":{"threshold":0.001,"maxIterations":200,"lambda":0.8}}'

curl -X POST http://localhost:8080/api/sensitivity \
  -H 'Content-Type: application/json' \
  -d '{"edgeId":"edge-e1-c1","targetNodeId":"c1","options":{"threshold":0.001,"maxIterations":200,"lambda":0.8}}'
```

## 本地开发（可选）

Docker 是推荐且唯一需要的部署方式。若要在本机开发：

```bash
npm install
npm run dev
```

- 前端 Vite：<http://localhost:5173>
- 后端 API：<http://localhost:8080>
- Vite 已将 `/api` 代理到后端。

生产构建：

```bash
npm run build
npm start
```
